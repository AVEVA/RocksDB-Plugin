# cachelib-navy overlay port

Builds only the SSD cache part of [CacheLib](https://github.com/facebook/CacheLib) (called Navy) as one static
library, `cachelib-navy::cachelib_navy`, for `CacheLibSecondaryCache`. Linux x64 only.

Building all of CacheLib pulls in many large dependencies that we don't need. This port compiles just the Navy
sources with its own [CMakeLists.txt](CMakeLists.txt), so the only new vcpkg dependencies are folly, magic-enum,
tsl-sparse-map, and xxhash.

A known limitation is that Navy reads and writes the cache file one request at a time on its own threads. It does not use Linux's asynchronous
I/O (io_uring), because the vcpkg folly package doesn't enable that support. Enabling it later would require
fixing that package and removing the `CACHELIB_IOURING_DISABLE` define.

## What is changed from upstream

Each change removes something we don't need or fixes a build problem with the vcpkg versions of folly and fmt.

| Item | What it does |
|---|---|
| `CMakeLists.txt` (port owned) | Compiles only the Navy sources. It leaves out Navy's tests and benchmarks, plus the test-only `MockDevice`, and adds the few shared helper files Navy needs. |
| `shim/` headers | Replace code that is normally generated by Thrift (a serialization tool) with plain structs, and replace the serializers with stubs that throw. Navy only serializes this data to keep the cache across restarts. This plugin never does that: the cache file is wiped on open and `Driver::persist()` is never called. |
| `0001-remove-test-only-dependencies.patch` | Removes dependencies that only exist for Navy's tests (gtest and gmock). |
| `0002-header-only-numa.patch` | Replaces the libnuma library (LGPL license) with a small header that makes the same Linux system calls directly. Navy never pins memory to a NUMA node, so these calls are never made in practice. |
| `0003-build-fixes.patch` | Fixes compile problems against the vcpkg folly and fmt versions: enum formatting that fmt 12 no longer does implicitly, a folly feature that isn't available, and libaio code that must be skipped when libaio is missing. |

The part of CacheLib that caches in memory (`CacheAllocator`) is not built. RocksDB's block cache is the in-memory tier.

## Memory use

Navy keeps a small amount of DRAM. The fixed parts can be predicted from the options, but the index grows with the
number of cached entries, so there is no single setting that caps total RAM.

| Item | Size |
|---|---|
| Request-ordering bookkeeping | About 4.5 MiB by default on Linux x64 (`72 * 2^16` bytes, set by `requestOrderingShardsPower`) |
| Region buffers | 8 MiB by default (`2 * cleanRegions * regionSizeBytes`) |
| Thread stacks | Fixed by the reader and writer thread counts |
| Index | Grows with the number of cached entries, so a larger cache of smaller blocks needs more |
| Queued inserts | Bounded by the parcel limit (`maxParcelMemoryMB`, 32 MiB by default in this plugin) |

The parcel limit bounds queued insert payloads only. It is not a total RAM limit or an upfront allocation.

References:
- [CacheLib: Configure HybridCache](https://cachelib.org/docs/Cache_Library_User_Guides/Configure_HybridCache/) covers the
  request ordering shards, parcel memory, thread and region settings.
- [CacheLib: Navy overview](https://cachelib.org/docs/Cache_Library_Architecture_Guide/navy_overview/) covers the design
  goal of low DRAM overhead, the job scheduler and the admission limits.

## Updating CacheLib

1. Change `version-string` in [vcpkg.json](vcpkg.json) to the new CacheLib release tag (without `v`)
   and set `SHA512` in [portfile.cmake](portfile.cmake) to `0`; the first build prints the real hash.
2. Re-apply the patches (`git apply --3way`) and regenerate them if they drift.
3. Diff `cachelib/navy/CMakeLists.txt` upstream against the source list in [CMakeLists.txt](CMakeLists.txt).
4. Diff `cachelib/navy/serialization/objects.thrift` and `cachelib/common/BloomFilter.thrift` against the
   shim structs; add any new fields or structs.
5. `grep -rn 'gtest\|gmock\|numa.h\|thrift/' cachelib/navy cachelib/common cachelib/shm` for new includes.
6. Run the full plugin test suite on Linux (`ctest --preset LinuxDebug`).

A vcpkg `builtin-baseline` bump (Dependabot) can change folly; the same test run covers that.
